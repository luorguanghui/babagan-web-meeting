# Production deployment record

This file is a target-host evidence template. It is not evidence that production was deployed. Do not record passwords, API secrets, LiveKit Tokens, participant data, media, or real private keys.

| Field | Value |
|---|---|
| Release Git SHA | Pending target-server execution |
| Operator and UTC timestamps | Pending target-server execution |
| Image IDs/digests and release record path | Pending target-server execution |
| Database backup path and SHA-256 | Pending target-server execution |
| Application directory and environment-file path | Pending target-server execution |

The exact restricted-SSH evidence strings accepted by scripts/firewall-attestation.sh are:

~~~text
Alibaba inbound: TCP 80,443,3478,5349,7881; UDP 443,3478,49160-49200,50000-60000; SSH restricted
Host firewall: TCP 80,443,3478,5349,7881; UDP 443,3478,49160-49200,50000-60000; SSH restricted; default deny inbound
~~~

Store evidence outside Git with mode 600:

~~~bash
sudo install -d -m 700 /root/babagan-protected
sudo chmod 600 /root/babagan-protected/network.txt /root/babagan-protected/cloudflare.txt
~~~

## Normal update command

Run only after local tests pass, the checkout points at the intended full SHA, and no pending-release.env exists:

~~~bash
cd /opt/babagan-meeting
RELEASE_SHA=$(git rev-parse HEAD)
sudo bash scripts/deploy.sh \
  --confirm-deploy "$RELEASE_SHA" \
  --target-ip '<confirmed origin IPv4>' \
  --smoke-token-file /root/babagan-secrets/smoke-token \
  --network-evidence /root/babagan-protected/network.txt \
  --cloudflare-evidence /root/babagan-protected/cloudflare.txt
~~~

Use --env-file only when the production env is outside infra/.env.production. Use --allow-public-ssh only with the public-SSH evidence above.

The script performs all read-only checks first. It then creates a checksummed SQLite backup, writes mode-600 var/releases/pending-release.env, builds or pulls the pinned images, runs the migration, starts the candidate stack, waits for caddy/api/livekit/web/coturn to be healthy, and runs deployment-smoke.sh. The deployment smoke creates a disposable meeting and signs a fresh LiveKit Token; the static smoke-token-file is not the source of RTC freshness. When the protected env contains both `CLOUDFLARE_TURN_KEY_ID` and `CLOUDFLARE_TURN_API_TOKEN`, deployment-smoke.sh must also execute explicit `SMOKE_REQUESTED_TURN_PROVIDER=coturn` and `SMOKE_REQUESTED_TURN_PROVIDER=cloudflare` ICE checks in addition to the default request. On success, deploy.sh writes the release record, updates current-release.env, and preserves a completed pending record.

Preserve all of the following outside Git:

- deploy.sh stdout/stderr and the UTC start/finish time;
- var/releases/current-release.env and var/releases/releases/<SHA>.env;
- var/releases/releases/<SHA>.pending-completed.env;
- the SQLite backup and its .sha256 sidecar;
- docker compose ps, health endpoints, and deployment-smoke output;
- the default ICE smoke plus explicit `coturn` and `cloudflare` smoke output when Cloudflare credentials are configured;
- image IDs for api, web, caddy and livekit.

## Empty-server command

For a genuinely empty server only, after the Caddy certificate preflight in docs/04-deployment-and-operations.md:

~~~bash
cd /opt/babagan-meeting
RELEASE_SHA=$(git rev-parse HEAD)
sudo bash scripts/deploy.sh \
  --confirm-deploy "$RELEASE_SHA" \
  --target-ip '<confirmed origin IPv4>' \
  --smoke-token-file /root/babagan-secrets/smoke-token \
  --network-evidence /root/babagan-protected/network.txt \
  --cloudflare-evidence /root/babagan-protected/cloudflare.txt \
  --bootstrap-empty
~~~

The first release has no predecessor or database backup provenance. deploy.sh records a bootstrap-pending transaction and a candidate volume marker. If it fails, do not start another deployment; use the guarded --recover-pending-deploy command in the rollback record.

## Post-deploy checks

~~~bash
sudo docker compose --env-file infra/.env.production -f infra/docker-compose.yml ps
curl --fail --silent --show-error https://meet.babagan.cloud/health/live
curl --fail --silent --show-error https://meet.babagan.cloud/health/ready
curl --silent --output /dev/null --write-out '%{http_code}\n' https://meet.babagan.cloud/
sudo test ! -e var/releases/pending-release.env
~~~

Record the resulting DEPLOY SUCCEEDED: <SHA> line. A successful run must also show healthy services, HTTP 200 for the SPA, Cache-Control: no-store in the authenticated ICE response, successful RTC WebSocket open, cleanup of the disposable smoke meeting, and when Cloudflare credentials are configured, successful explicit `turnProvider=coturn` and `turnProvider=cloudflare` ICE checks.
