# 本机原生共享使用说明

这套入口使用电脑上的 DXGI 采集屏幕，再由 Edge 通过原来的会议传输共享。观看者继续使用现有会议网页。原生模式目前支持 Windows、一个活动显示器；其他情况可在网页里选择“浏览器采集”。

需要已安装 Node.js 24、支持 `ddagrab` 的 `dup_frames` 选项的 FFmpeg、Edge 和 PowerShell 7。打包版已包含本机组件的 JavaScript 依赖，不需要在包内安装 pnpm。FFmpeg 是外部依赖；启动器会验证该选项，旧版缺少支持时会明确拒绝，避免无更新时重复上一帧。此次本机另准备了校验过的 FFmpeg 9.0.2 便携运行时，没有替换系统原有 FFmpeg。

网页必须先更新到支持本机采集的版本。新入口启动后，地址中的一次性连接信息会被网页接收并从地址栏清除；旧网页不具备这个接入功能。

1. 解压后双击“启动本机共享.cmd”。FFmpeg 不在 PATH 时，在 PowerShell 中运行 `scripts/start-native-meeting.ps1 -Ffmpeg 'C:/Tools/ffmpeg/bin/ffmpeg.exe'`，把路径替换为实际位置。
2. 在打开的独立 Edge 窗口里创建或加入会议。首次按 Edge 提示允许该会议网站访问本机网络；不需要更改系统防火墙或关闭浏览器安全功能。
3. 保持“本机原生采集”“动态 1080p60”和“自动”编码，点击共享屏幕，在浏览器选择器里选择唯一的整屏；需要电脑声音时同时勾选声音。
4. 使用网页“停止共享”、浏览器“停止共享”或离开会议结束采集。系统声音的回声隔离提示仍按原流程处理。

自动编码会根据实际硬件能力优先选择 AV1，并保留 H.264 回退。原生模式默认码率上限 20Mbps，实际速率由网络拥塞控制调整；P2P 多观看者继续受总上行预算约束。手动选择码率仍有效。帧率统计与实际内容变化分开理解：静止画面没有新的像素变化，不能用它证明运动 60fps。

入口使用独立的 `%LOCALAPPDATA%/Babagan/MeetingEdge` 配置，不修改日常 Edge 或默认浏览器。首次可能需要重新登录。更新启动器后，请先关闭所有旧的专用会议窗口，再从新入口打开，以便新的性能参数生效。

正常浏览器共享仍可使用；关闭专用窗口后打开原来的 Edge 入口即可。后台本机服务在停止共享后不再采集，空闲 30 分钟自动退出。启动失败会给出明确错误，不会以“已就绪”掩盖缺失的 FFmpeg 或 Edge。

性能验收以实际收到的新画面、分辨率和运动期间表现为准。静止画面下的统计不能证明运动 60fps；跨网带宽不足、接收设备解码能力不足仍可能限制表现。测试记录应与具体版本一起查阅。

没有新采集帧时，组件最多每秒刷新一次旧画面以维持媒体连接，并单独记录 `refreshFrames`。这些保活帧不计入真实采集帧或运动帧率；不会通过重复画面把运动统计补到 60fps。
