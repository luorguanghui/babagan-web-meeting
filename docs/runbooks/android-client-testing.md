# Android 客户端手机验收

当前提供已签名的预览版 APK。源码测试与构建已通过；本机模拟器无法启动，真实手机验收由用户进行。不要把这些构建记录当作设备共享已通过的证明。

1. 从 Babagan 主页下载 Android APK，核对来源；安装所需的系统确认由手机用户操作。
2. 打开客户端，应直接显示会议工作台，不出现宣传页或客户端下载入口。加入一个测试会议，另一台电脑用普通 Edge/Chrome 网页加入即可。
3. 先测试麦克风通话，再点共享屏幕。按 Android 系统提示选择要共享的屏幕；每次新共享都需要系统确认。
4. 在会议共享设置中分别选择30帧和60帧（0.1.2起开放60帧）。打开不含隐私的测试网页，做持续快速横移/大范围滚动，并测试竖横屏旋转；检查电脑端实际帧率、分辨率与码率，不能只看“60帧”选项是否存在。留意手机温度升高后是否掉帧，以及快速运动是否出现明显色块。
5. 切到其它测试应用，确认共享与会议麦克风仍继续；静音/开麦都应及时生效。
6. 从系统共享通知停止，电脑端应回到等待共享，系统采集指示应消失。再开始一次，确认旧会话没有残留。
7. 离会、关闭客户端后应停止屏幕与麦克风服务。
8. 服务器发布新版本后，客户端启动/回到前台及前台每30分钟检查更新。会议/共享中只做小清单检查，安装与大文件下载等待空闲；Android 仍可能要求确认安装。

Android 0.1.2开放30/60fps采集配置，旧0.1.1仍按30fps能力运行；分辨率按屏幕方向适配1080p范围。选择60帧不代表所有手机都能持续产出60个不同画面，真实表现需本次手机验收。系统声音功能见下方开发版验收项，旧版客户端仍只传屏幕画面，会议麦克风独立可用。手机浏览器可语音与观看，发起设备屏幕共享需使用 Android 客户端；电脑网页仍可直接发起共享。

若异常，记录手机型号、Android版本、客户端版本、传输模式及具体操作顺序。统计截图只需包含测试内容，不要发送私人应用画面、密码或授权令牌。

## 0.1.4 画中画和音频路由

1. 确认客户端版本为0.1.4。安卓客户端的入会页面不应再显示“移动设备仅支持观看和语音”的浏览器限制提示；这不取消会议本身的共享授权和Android系统采集确认。
2. 接收另一位成员共享的测试画面，点击“小窗观看”。切到其他不含隐私的应用，检查系统小窗是否仅显示共享视频，且画面/声音继续；再用系统展开操作返回会议，检查没有重复播放或重音。
3. 让发送端结束共享。小窗应显示结束提示，系统展开后回会议；普通共享结束不应主动把其他应用挤出前台。系统X关闭可能按Android行为销毁客户端，不等同展开返回。
4. 在音频设置选择通话设备，分别试外放、听筒及已连接耳机。界面显示实际输出设备，麦克风由Android随通信路由自动匹配；不承诺任意输入输出独立组合。
5. Bluetooth访问只在主动点击允许按钮时请求；授权后仍需选择耳机，不能自动改变当前设备。实际听声音，并请对方确认麦克风来源；拔掉耳机后检查设备列表与实际输出及时更新。
6. 切换路由不应自动取消静音，进入PiP/后台不应释放正在使用的通话路由；离会后检查手机其他应用的音频恢复正常。

网页的隔离接口测试和JVM生命周期测试不能替代上述真实设备行为。手机系统若禁用Babagan的画中画或Bluetooth权限，需要用户在系统中允许；客户端不会绕过这些设置。

## 开发版：共享设备声音与回音隔离

本项要求安装包含播放捕获实现的构建，并使用 Android 10（API 29）或更新版本。当前实现和自动测试已完成，尚未在真实手机验证；本节是待执行的设备验收步骤。

1. 保持会议麦克风静音，选中“共享设备声音”，同意录音权限与屏幕共享授权。播放同一用户配置文件内允许捕获的测试应用媒体，电脑应同时收到画面与声音。音量、声道和音画同步需实际听辨；本机测试不能证明手机采集音质。
2. 让会议另一位成员说话、播放远端共享声音。本机可正常收听，屏幕共享接收方不应从这条屏幕音轨再次收到会议声音；开关会议麦克风不应改变设备声音选项。原生播放捕获排除 Babagan 自身 UID，屏幕音轨不混入麦克风，麦克风自身的声学回音仍由独立通话链路处理。
3. 拒绝录音权限后允许屏幕共享，应继续传画面并显示权限提示。取消“共享设备声音”再开始，不应创建播放录音器，也不应从麦克风替代采音。
4. 测试允许与禁止播放捕获的两个测试应用。受保护应用输出静音是预期限制，不能据此声称所有应用均可录制。Android 只允许匹配 `USAGE_MEDIA`、`USAGE_GAME`、`USAGE_UNKNOWN` 且源应用允许捕获的播放内容；DRM、通话及其他禁止捕获的内容不保证有声音。不同用户或工作配置文件也受系统限制。
5. 从系统通知停止、撤销共享授权、离会和关闭客户端，再重新开始一轮。旧画面、旧音频及系统采集指示应结束，新共享应有新的系统授权，不应出现重复声音。旋转和切后台后也检查音画继续。
6. 原生音频读取失败时应仅结束共享音轨，保留屏幕画面并显示设备声音不可用。普通浏览器的回音风险检查应保持；已确认排除本应用的 Android 音轨不再出现浏览器专用的回音风险选择。
7. 在尚未授予权限的测试安装中，通知权限、麦克风、共享设备声音和 Bluetooth 请求应依次弹出；麦克风与共享声音同时等待时合并为一次录音权限请求。明确拒绝录音后仍可继续仅画面共享；中断权限交互产生空结果时应取消本次共享，不应自行弹出投影授权。等待期间取消网页麦克风、离会或导航后，旧请求的返回不能启动录音或屏幕投影；系统弹窗真正返回前也不能抢占其请求槽。

### 实现边界与核验依据

- 继续使用现有 `ScreenCapturerAndroid`；读取它公开的 `getMediaProjection()`，将同一个授权实例交给 `AudioPlaybackCaptureConfiguration`。不再次兑换授权 Intent，不创建第二条屏幕投影路径。
- 使用已有、固定版本的 `io.github.webrtc-sdk:android:144.7559.15`。已对本机安装的 AAR / runtime JAR 执行 `javap`，核对公开的 `setAudioRecordEnabled(false)` 与 `setAudioBufferCallback`。前者在工厂创建前关闭 SDK 内置麦克风录制，后者将 48 kHz、双声道 PCM16 缓冲写入原生 WebRTC 音轨；没有使用反射或替换私有字段。
- JVM 测试通过真实 SDK `AudioBufferCallback` 接口检查 PCM 写入、部分读取、静音、缺少权限、版本不支持、启动失败、运行时失败和停止期间的资源所有权。网页测试检查先后到达的音视频轨、拒绝权限后的降级、音轨结束、重复事件和回音检查；这些测试不代替 Android 平台录制验证。
- 原生启动结果只有在录音器可用时确认 `systemAudioExcludesOwnApp`。网页仅给该会话接收的音轨登记模块私有标记；普通音轨即使修改 `getSettings()` 也不能冒充这项原生隔离能力。
- Activity 的所有运行时权限统一通过 `RuntimePermissionQueue`：按权限合并等待者、按系统回调释放弹窗占用，并在投影确认期间暂停新的运行时弹窗。空权限结果按 [Android 回调文档](https://developer.android.com/reference/android/app/Activity#onRequestPermissionsResult(int,java.lang.String[],int[])) 作为取消处理。纯 JVM 测试验证队列和所有权；实际系统弹窗次序仍需上述设备验收。

参考：[Android 播放捕获要求](https://developer.android.com/media/platform/av-capture)、[SDK 可写 PCM 回调与音频设备接口](https://github.com/webrtc-sdk/webrtc/blob/m144_release/sdk/android/api/org/webrtc/audio/JavaAudioDeviceModule.java)、[SDK 回调执行路径](https://github.com/webrtc-sdk/webrtc/blob/m144_release/sdk/android/src/java/org/webrtc/audio/WebRtcAudioRecord.java)。SDK 分支链接用于说明接口，当前实现的可用性另由上述固定 AAR 的字节码与编译结果核对。
