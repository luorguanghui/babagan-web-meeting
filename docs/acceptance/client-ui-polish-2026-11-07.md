# 客户端界面优化与 Android 全屏修复

三项界面修改保持原流程：创建会议页使用工作台的亮白/鲜橙/深灰配色；工作台顶部展示更新状态、版本和检查按钮；Android设备或手机宽度优先排列Android下载，宽屏桌面优先Windows。下载排序改变真实DOM顺序并响应窗口大小，不以CSS视觉顺序代替键盘/读屏顺序。

本地CUA验收：桌面720px高视口内更新按钮底部约233px，手机390×844视口内约304px，均无需滚动；手机无横向溢出。下载列表在390px为Android→Windows，切换1280px后为Windows→Android。创建会议页面的表单、校验和权限行为保持原样。

Android全屏故障原因是WebChromeClient未实现onShowCustomView/onHideCustomView；官方文档明确未实现时会向页面报告不支持全屏。0.1.3/code4接入通用custom view及系统栏隐藏/恢复；返回键优先退出全屏，导航/销毁幂等释放，原WebView不隐藏、不重载，旋转保留既有Activity。原同源与SSL限制不变。Windows同步版本0.1.3用于配对签名发布序号4，原生媒体流程没有修改。

检查：74个网页测试文件/864项测试、web类型检查与修改源码lint通过；Windows37项更新/入口检查通过；Android33项JVM测试、Debug构建及lintDebug通过。独立复查无阻断项。安卓系统栏、旋转、返回键及媒体连续性仍需真机验收，不能用JVM测试替代设备测试。

按用户要求，先合并main，再以合并后的干净源码构建网页和正式签名产物。部署沿用只读下载卷和既有运行时，仅替换Web；随后独立发布0.1.3/seq4，保留旧版本资源。服务器发布记录包含回滚路径、文件哈希和容器身份验证。最终公网下载及旧客户端升级结果保存在该次发布验收输出中。
