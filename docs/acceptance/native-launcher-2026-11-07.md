# 原生共享恢复与 Windows 启动器验收（2026-11-07）

## 范围与证据边界

用户确认原生共享已解决原先丢帧和色块，新增要求为：应用启动时共享退出的恢复、固定所选每观看者上限、默认 10 Mbps、网页提供安装器和所有依赖、桌面入口、复用兼容的已安装依赖。禁止启动游戏；测试均使用合成源，没有共享用户桌面。

用户报告发送端也回到未共享状态。现有代码在 FFmpeg 退出后关闭 HTTP 流并触发轨道 ended，缺少恢复；官方 DXGI 文档规定桌面切换/显示模式变化可能丢失复制接口，FFmpeg 对 AcquireNextFrame 失败或 Output parameters changed! 退出。真实游戏启动时的具体错误未捕获，不能认定每次退出均来自 DXGI；浏览器授权轨道 ended 仍须尊重。

## 实现

- 在同一授权流中，仅对明确的 DXGI/输出参数变化进行最多 8 次、单次恢复窗口最多 20 秒的重建。重新核对单显示器，保持分辨率与单调时间戳；停止/撤销/不支持布局会终止。
- 取消画质、名单和停止/重启自动提高上限。普通/原生默认每观看者 10 Mbps，手选持久化。SFU 回退 min(所选上限, SFU 上限)。视频目标码率与 RTP/音频/重传开销区分。
- Windows 无控制台启动器：隐藏 Node/FFmpeg，显式正常显示 Edge，单实例托盘、启动检查、错误与事件日志、退出/父进程断开清理。
- 安装器仅从 meet.babagan.cloud 下载固定 SHA-256 的依赖。先复用兼容的系统或 Babagan 已有依赖；仅缺失项下载、验证、安装。中文和带空格路径支持，生成桌面与开始菜单快捷方式。
- 原下载归档和许可证保持完整；脚本清单包含版本、来源和校验值。API/媒体服务不变。

## 白框验收

旧脚本使用 windowsHide:true 和 detached:true 启动可见 Edge。修正为正常可见 GUI 启动；此机残留 10 个专用配置后台进程、没有可见窗口且无 FFmpeg 采集，清理仅该配置后重新启动。用户明确确认“会议网页正常，白框已消失”。没有把截图本身当作进程归属证明；UI 验收结论来自本次重启后的用户实际观察。
