# 会议关闭确认与安卓后台音频

日期：2026-11-03，目标设备为安卓 Chrome / Edge。基线 `dc07f5516b97f4bac665ecae55fbd8bddad6339b` 已推送 GitHub main。

## 行为

- 房主和参会者在会议页面激活 `beforeunload`，关闭标签页、刷新、整页跳转时请求浏览器原生确认。点击应用内离开或结束会议后解除监听；切后台不会被当作退出。
- 浏览器控制确认框文字，不能保证显示自定义“正在会议中”。确认要求用户曾与页面交互；安卓直接关闭标签页、关闭进程等路径可能不触发该事件，不能承诺全部关闭操作均有弹窗。参见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)。
- 语音继续使用原生音频元素；屏幕共享声音改为独立的音频元素，播放从既有接收流提取的音频轨道或 LiveKit 音频轨道，不额外采集、不重复订阅。视频始终静音，视频后台暂停不影响音频元素。音频切换不再等待后台视频首帧，画面仍保留原来的首帧切换逻辑。
- 注册 Media Session 会议标题和恢复播放/挂断操作，便于系统媒体控件管理实际会议声音。这不是阻止系统回收进程的保证。
- SDK 重连先保留既有音频连接；完全断开后重新获取同身份 Token。移除 30 秒后强制返回入会页的策略，改为单次请求限时 30 秒、最多 10 秒间隔重试。服务器会话失效、被移出或会议结束仍是终态，不能靠重连绕过权限。
- 回到前台、网络恢复、页面恢复时恢复播放并重试断线。原生 SDK 已恢复的连接会取消过期的应用层重连。主动离开前取消所有恢复工作。

## 验证及边界

回归先在原版失败：后台完全断开不重连、SDK 恢复时被应用层立即替换、关闭没有确认。独立审查另补上 SDK attach 改变 muted 导致重音、延迟 token 替换健康连接，以及音频不应等待后台视频帧的回归。

`qa/background-listening.html` 仅为本地开发验证入口，使用生成的轻声测试音与画布，不访问麦克风、摄像头或真实会议，也不进入生产构建。

普通切换 App 时，网页保持音频播放；浏览器或系统强制冻结/回收进程、断网时，任何网页均无法继续接收实时媒体。代码与桌面浏览器检查不能替代实体安卓的锁屏/省电策略验收。参考 [Chrome 页面生命周期](https://developer.chrome.com/docs/web-platform/page-lifecycle-api) 与 [Media Session](https://web.dev/articles/media-session)。

最终测试、浏览器证据及上线记录存于 `output/background-audio-deploy-20261103/`，部署后追加实际结果。

已完成：77 个测试文件、994 项测试通过，Web 类型检查、修改文件 ESLint、生产构建通过。独立审查提出的三个问题均已修复。

桌面 Edge 测试先关闭调试器的前台模拟后，通过 CDP 读到真实 `visibilityState=hidden`，测试音频进度达到 98.052 秒，`paused=false`、`muted=false`，独立播放器含一条音频轨道、零条视频轨道。该证据仅为桌面后台测试，不是实体安卓锁屏证明。关闭确认目前由 beforeunload 取消事件的自动化回归验证，未声明已目视验收所有浏览器的原生弹窗。

后续原生浏览器检查因 Computer Use 无法可靠确认 Windows 当前浏览器 URL，被安全检查终止。本轮保留本地发布包并提交 GitHub，新功能尚未通过服务器终端激活；线上当前仍为前一轮 `dc07f55`。
