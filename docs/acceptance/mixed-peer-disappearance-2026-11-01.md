# P2P／TURN 混合接收首帧后消失

用户场景：一名共享者选择浏览器 P2P 共享，三名接收者，其中无法直连的接收者自动走 TURN。接收端短暂出现画面后回到等待，共享者本地预览和共享状态仍正常；Cloudflare SFU 正常。

## 可复现的失效链路

`P2pSignalingSession` 原先把一条 WebSocket 的全部消息共用 120 条／60 秒额度。共享者对每名观看者建立独立 PeerConnection，却把所有连接的 trickle ICE 候选汇到同一个 WebSocket；host、STUN、TURN 候选在首帧之后仍可能继续到达。

使用真实 WebSocket 路由建立共享者和三名接收者，先完成 offer 和 media-ready，再交替发送每名接收者 42 个候选。旧代码可稳定得到 `RATE_LIMITED`，关闭共享者信令并广播 `peer-left`。这是信令层失效，不要求编码器或采集停止。页面把信令离线立即当作共享者离会，关闭接收 PC 并清空舞台，所以发送者预览正常，接收端却显示等待。

没有取得用户原始会话的信令导出，因此不能断言该次会话恰好发送了 42 个候选；该数字是覆盖三路候选聚合超限的回归输入。已在服务端真实 WebSocket 测试和接收页面状态测试分别复现这条完整失效链路。Cloudflare 主媒体不依赖这些逐观看者的 P2P 协商，能避开这条触发路径。

## 修复

- 控制消息仍为每连接 120 条／60 秒。已授权且在线目标的 ICE 改为每目标独立额度，generation 改变不重置；最多四个目标桶，离开／重新加入不能无限扩大额度。其他候选仍消耗控制额度，原有 64 KiB 单消息限制及鉴权不变。
- 已接收到屏幕时，`peer-left` 或重连 welcome 暂缺共享者不立即销毁媒体，给信令 30 秒恢复窗口。收到共享者 peer-joined、welcome 或新 offer 时取消计时器。
- 真正的 bye／share-gone 仍立即清理；无媒体的协商不保留；超时不返回的共享者被清理，防止永久残留。旧身份的延迟清理不能关闭另一个共享者的新会话。
- 编码 profile、帧率、码率、传输选择和 Cloudflare 媒体流程没有变化。

## 验证

- 三接收者真实 WebSocket 回归：旧代码返回 `RATE_LIMITED`，修复后候选全部转发、pong 正常、共享者仍在线且没有 peer-left。
- 接收页面回归：旧代码在信令离线后关闭 PC；修复后保持同一 MediaStream，重新上线取消清理；share-gone 及 30 秒超时仍能关闭。
- 覆盖单目标滥发、控制消息滥发、非法／离线目标、目标身份轮换及固定窗口重置。
- 全量 74 个测试文件、979 项测试通过，API 与 Web 构建、修改文件 ESLint 通过；独立代码审查无阻断问题。

发布包同时包含网页和本地编译的 `apps/api/dist/p2p/signaling-session.js`。API 运行镜像沿用原 Linux 依赖，只替换这一无新增依赖的模块；源码差异检查拒绝其他 API 生产变更或迁移。候选镜像须先在断网容器内通过“三路各 42 个候选保持在线、控制消息滥发仍拒绝”的测试，才能切换 API 和 web。
