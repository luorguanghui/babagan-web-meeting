# P2P Transport Visibility and TURN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox notation for execution tracking.

**Goal:** Make the WebRTC statistics panel consume the active screen-share transport, show an accurate Chinese transport-mode badge, and let custom P2P screen share succeed through a same-host coturn relay when direct ICE cannot connect.

**Architecture:** Keep LiveKit screen publishing as the always-on SFU safety net. The custom screen-share controllers expose stats from their own `RTCPeerConnection` instances and classify the selected ICE candidate pair as direct, relay, or unknown. The authenticated ICE endpoint returns STUN plus short-lived TURN REST credentials generated by the API. A host-networked coturn container uses the existing public server, a narrow UDP relay range, and a Caddy-managed certificate mounted read-only.

**Tech Stack:** TypeScript 5.9, React 19, WebRTC APIs, Fastify 5, Node `crypto`, Vitest/Testing Library, Docker Compose, Caddy 2.10, coturn 4.17.2-r0.

## Global Constraints

- Preserve LiveKit Server v1.11.0 and its existing UDP 443 embedded TURN listener.
- Keep SFU screen publishing active while P2P/TURN is in use so fallback remains immediate.
- Never expose the coturn static secret to the browser; issue participant-bound credentials with a 600-second lifetime.
- Do not label a connection until a nominated/succeeded selected candidate pair is known.
- Do not add telemetry collection or consent changes in this work.
- Pin coturn to `coturn/coturn:4.17.2-r0@sha256:aa68aab64a3b929d57fc2924c98ea447bf996cf8dade2508e7b71eaf23f1f14e`.
