## 背景与目标

当前 P2P 分支已经实现信令、浏览器端连接控制、按观看者回退和自动化测试，但审查发现它不能安全投入生产：固定版本 LiveKit 不提供实现所调用的 `/rtc/ice` 接口；P2P 成功后取消 SFU 发布会让旧客户端黑屏；ICE connected 不能证明媒体仍在流动；回退时先销毁旧源会制造黑屏；WebSocket 缺少 Origin 校验；质量统计未经用户同意自动上报。

本轮加固的目标是：P2P 仅在确认直连媒体健康时用于观看，SFU 始终作为兼容且可无缝恢复的安全网；任何 P2P、信令或浏览器能力故障均不得使体验劣于现有 LiveKit 屏幕共享。

## 核心架构决策

### 1. ICE 只使用受支持的显式配置

- 删除对 LiveKit `/rtc/ice` 的调用、缓存和相关固定 TTL。当前固定的 LiveKit Server 版本没有这个 HTTP 路由，嵌入式 TURN 也依赖已建立的 LiveKit 信令会话，不能视为通用 P2P TURN 服务。
- API 从 `P2P_STUN_URLS` 读取逗号分隔的 `stun:` URL，经参与者会话鉴权后由现有 ICE 配置端点返回。生产配置至少需要一个 STUN URL；测试环境可以显式配置空列表来验证 host candidate。
- P2P 控制器通过 `RTCPeerConnection.getStats()` 检查选中的 candidate pair。只有 host、srflx 或 prflx 直连对才计为 P2P；relay 对不计入直连成功，并切回 SFU。这样即使未来增加独立 coturn，也不会把云端中继误报为 P2P 节省带宽。
- 若业务以后需要提高复杂 NAT 下的 P2P 覆盖率，独立 coturn 是后续部署选项，不在本轮复用 LiveKit 内部 TURN。

### 2. SFU 保持发布，观看端按需取消订阅

- 共享者开始共享时，必须先成功发布 LiveKit 屏幕视频/音频，再启动 P2P 协商。SFU 发布失败时启动操作失败并显示可行动的中文错误，不得吞掉异常或显示“正在共享”。
- 共享期间 SFU 发布始终保持。P2P 只减少支持新协议的观看端的 SFU 下行订阅，不取消共享者到 SFU 的安全网。旧客户端、未连接 P2P 信令的客户端和 P2P 失败的客户端继续走 SFU，因此滚动发布期间不会黑屏。
- 新观看端只有在 P2P 视频首帧已渲染、RTP 正在增长且 candidate pair 确认为直连后，才向信令发送 `media-ready`，并取消本端 LiveKit 屏幕轨道订阅。
- 共享端收到 `media-ready` 后才把该观看者标记为 `p2p`。ICE connected 本身只表示传输连接建立，不能触发成功状态。

该方案会保留一份共享者到 SFU 的上行，因此准确目标是减少 P2P 观看端对应的云端出站带宽，而不是宣称云端对屏幕媒体完全零带宽。

### 3. 无黑屏回退与持续媒体健康检测

- 观看端每秒采样选中连接和 `inbound-rtp`：记录 `bytesReceived`、视频 `framesDecoded` 与最近增长时间。视频 RTP 连续 5 秒无增长、ICE failed、ICE disconnected 持续 5 秒、信令失联或共享者发送 `share-gone` 均进入回退。
- 回退顺序固定为：重新订阅 LiveKit 屏幕轨道 → 等待轨道到达并确认首帧 → 原子切换渲染源 → 关闭 P2P 连接并发送 `bye`。若 SFU 新源尚未就绪，保留并继续显示最后一个 P2P 帧，不清空 `MediaStream`。
- `ScreenStage` 继续负责双源首帧切换，但控制器不得在新源就绪前清空旧源。切换目标保持画面空白不超过 2 秒；超过时显示明确的重连状态，而不是空白画布。
- P2P 恢复不自动来回抖动。同一次分享在回退后保持 SFU，下一次分享或明确重新协商时再尝试 P2P。

### 4. 能力与旧客户端兼容

- P2P WebSocket 在线名单只代表“具备本版本 P2P 能力”的参与者，不能替代 LiveKit 房间成员名单。
- 共享者只对同时存在于 LiveKit 参与者列表和 P2P 能力名单中的观看者创建 PeerConnection。其他参与者自然保持 SFU 订阅。
- 信令重新连接后重新对比两份名单；身份不存在、已经离会或不再获授权的连接立即关闭。
- 新协议增加观看者到共享者的 `media-ready` 消息；服务端仍强制消息双方同会议、目标为当前共享者，并校验消息大小和方向。

## 安全与隐私

- P2P WebSocket Upgrade 是 GET 请求，不能依赖只覆盖 POST/PUT/PATCH/DELETE 的通用 Origin Hook。路由在 Cookie 鉴权前显式校验 `Origin`，仅接受配置的 meet 来源；缺失、格式错误和跨站 Origin 均拒绝，覆盖自动化测试。
- 继续禁止记录 SDP、ICE candidate、ICE 凭据和对端 IP。现有设计文档中的真实公网 IPv4 改为脱敏描述，测量证据只保留网络类型、地区粒度和吞吐区间。
- 删除离会、卸载和会议结束时的自动质量上报调用。客户端可以保留仅本机会话可见的诊断计数；在产品提供明确的用户同意界面前，不向 API 上传 P2P 质量统计。

## 配置与生命周期

- 新增并校验 `P2P_STUN_URLS`。URL 必须使用 `stun:` 或 `stuns:` 协议；非法值在服务启动时失败。部署示例和冒烟测试同步更新。
- 协商 8 秒、断连 5 秒、RTP 停流 5 秒作为同版本前后端共享的协议常量，不再在文档中声称存在未实现的 `P2P_ICE_*` 环境变量。若以后需要运行时调整，另行设计版本化配置响应。
- 会议结束、过期清理或共享锁释放时，应用服务必须通知 `P2pRoomRegistry`：广播 `share-gone`，关闭对应会议的信令连接并释放注册表条目。后台清理路径与 HTTP 主动结束路径使用同一个终止回调，避免只修其中一条路径。

## 错误处理

- 初始 SFU 发布失败：终止共享启动、清理本地媒体轨道和 P2P 资源，并向用户显示“屏幕共享发布失败，请检查网络后重试”。
- P2P 初始化、STUN 配置或信令失败：保留已经工作的 SFU 分享，记录不含敏感字段的本地诊断状态，不打断会议。
- SFU 回退重新订阅失败：继续保留最后可用画面并显示“正在恢复屏幕共享”；按有限退避重试，会议结束或分享停止时取消。
- 所有异步清理均幂等，组件卸载、轨道 ended、主持人结束会议和后台过期可以重复调用而不产生未处理 Promise rejection。

## 测试策略

实现采用失败测试先行，至少覆盖：

- API：受信/缺失/跨站 WebSocket Origin；STUN 配置解析与鉴权；会议主动结束和后台过期均关闭 P2P 房间；不再调用 `/rtc/ice`。
- 协议：`media-ready` 只能由观看者发给当前共享者，越权和未知目标被拒绝。
- 共享端：ICE connected 不会提前判定成功；只有 `media-ready` 标记 P2P；SFU 发布始终保留；发布失败向上抛出。
- 观看端：首帧和 RTP 增长后才成功；RTP 停流 5 秒触发回退；relay candidate pair 不算直连；SFU 首帧前不关闭或清空 P2P 源。
- 兼容性：旧客户端不在 P2P 名单时仍收到 SFU；新旧客户端同时参会时互不影响；P2P 信令故障时屏幕共享仍可用。
- 隐私：页面卸载、离会和会议结束均不会自动 POST 质量统计。
- 质量门禁：lint、typecheck、单元/集成测试、构建，以及 Chromium 和 Edge 的 P2P/SFU 切换 E2E 全部通过。

浏览器 E2E 的 loopback candidate 和 fake LiveKit 只能验证控制流，不能替代真实网络验收。上线前还需在公网直连、双 NAT、受限 UDP 和 TUN 代理场景记录 candidate pair、首帧时间与回退时间；记录中不得保存完整 IP。

## 可行性结论

在单会议最多 5 人、单共享者、SFU 常驻安全网的约束下，此方案可行。直连成功时可减少对应观看端的云端出站流量，并绕开部分 SFU 下行波动；直连失败时体验回到现有 LiveKit 路径。它不保证所有 NAT 环境都能直连，也不再把 LiveKit 内部 TURN 当作通用 TURN 服务。若未来要求在复杂 NAT 下仍保持高直连/中继成功率，需要部署并运维独立 coturn，并重新评估云端带宽与凭据生命周期。
