# 共享画面扩展与全屏入口设计

## 目标

共享屏幕开始后，优先扩大共享内容的可视面积，并让全屏入口在普通页面中容易发现，同时避免它在真正全屏状态下遮挡内容。

## 设计

- 会议室根据本地或远端是否存在屏幕共享，切换 `meeting-room-sharing` 布局状态。
- 桌面宽屏下，共享画面横跨会议室全部可用宽度；成员列表和主持人控制区移动到画面下方。未共享时保持当前双栏布局。
- 共享画面仍使用 `object-fit: contain` 和 16:9 展示框，避免裁切源画面。
- 全屏入口保留在共享画面右上角，使用 40×40 像素高对比图形按钮、清晰边框和阴影，不显示大段文字。
- 进入浏览器全屏后，按钮继续通过 `fullscreenchange` 状态和 `:fullscreen` CSS 双重隐藏。
- 空共享状态不显示全屏入口。

## 响应式行为

- 小于 64rem 时沿用单列布局，共享画面自然占满页面宽度。
- 大于等于 64rem 且有共享时，主画面跨越两列；成员区和主持人区在其下方并排。仅有一个区块时正常占用对应列。

## 验证

- 组件测试验证有共享时会议室获得宽屏状态类，无共享时不获得。
- 组件测试验证共享时存在全屏按钮，触发浏览器全屏请求，并在全屏状态下隐藏。
- 完整运行测试、类型检查、Lint 和生产构建。
